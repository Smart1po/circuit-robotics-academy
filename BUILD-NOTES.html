The spine

Three decisions everything else hangs off. Get these wrong and the rest fights you.

One animation loop

Drop in

Every moving thing subscribes to a single requestAnimationFrame loop instead of starting its own. Glitter, sprites, dust, flyers, the roaming crowd, parallax — all one frame.

Subscribers are functions taking (dt, now). The loop stops rescheduling when nobody is subscribed, and pauses on visibilitychange.

BitesNever read layout (clientWidth, offsetWidth, getBoundingClientRect) inside the loop. Measure once, cache it, re-measure on resize. Reading layout 60×/second is the difference between smooth and juddering.

pixel.js → Ticker

The motion switch

Drop in

One switch controls every animation on the site, and the visitor can move it in both directions.

JavaScript writes data-motion="on|off" on <html>, seeded from the OS preference and then from the visitor's stored choice. Every animation asks that attribute, never the media query.

BitesScope every reduced-motion rule to html:not([data-motion]) — the no-JavaScript fallback. A bare @media (prefers-reduced-motion) rule silently overrides a visitor who deliberately turned motion back on. This cost us six features that were built and invisible.

app.js → initMotionToggle · CSS at the bottom

Content is never hidden by decoration

Drop in

Any effect that hides something must be armed by JavaScript after it has already revealed whatever is on screen — and needs a timer as a backstop.

/* CSS: hiding only applies once JS has armed it */
html.reveal-armed [data-reveal]        { opacity: 0; transform: translateY(14px); }
html.reveal-armed [data-reveal].is-in  { opacity: 1; transform: none; }

JS reveals everything currently in the viewport, then adds reveal-armed, then observes the rest. A 1.2s timer catches anything the observer misses. No script, no observer, no problem — the page is simply visible.

BitesThe naive version leaves a block permanently invisible if the observer never fires for it. Text that never appears is far worse than a missing animation.

Identity

No image files anywhere on the site. Both of these are text expanded into pixels at runtime.

Bitmap typeface

Some wiring

A 5×7 typeface written by hand — seven rows of five characters per glyph — turned into SVG rectangles at runtime.

'A': '.###.|#...#|#...#|#####|#...#|#...#|#...#'

Runs of lit pixels merge into single rects (a headline drops from ~600 to ~200). The scale is always a whole number computed from the container width, so pixels never land on half-device-pixels.

BitesKeep the real sentence in the DOM as visually-hidden text and mark the SVG aria-hidden. Otherwise the heading is invisible to screen readers and to anyone whose JS never arrives.

pixfont.js · <h1 class="px" data-px="LINE ONE|LINE TWO">

The mark, shining

Rebuild

A pair of wings that spread when the lights are on and fold when they're off, shining three ways at once.

A CSS halo that breathes behind it; four twinkle points on staggered delays; and a nova drawn into the sprite itself — a ring of white expanding through every feather across eleven frames.

BitesA gradient painted into artwork looks flat. Light travelling across a surface is what reads as depth — animate the light, don't bake it.

The world

Ambient life. All of it sits behind opaque content panels, so none of it can ever reduce the contrast of a word.

Sprite engine

Drop in

Every character is a text pixel map. One letter is one pixel, a dot is transparent, and a palette maps letters to colours.

var BOLT_A = [
  '..oooooooooooo..',
  '..obccbbbbccbo..',   //  o outline   b body
  '.otttttttttttto.',   //  c sensor    t tread
];
{ frames: [BOLT_A, BOLT_B], palette: P, fps: 5, scale: 3 }

Expanded onto a small canvas with imageSmoothingEnabled = false. Frames advance on the shared ticker; an IntersectionObserver stops off-screen sprites costing anything. Mount by putting data-sprite="bolt" on any element.

BitesValidate that every frame is rectangular and every character exists in the palette — a one-character typo in a 20-row map is invisible until it renders wrong. A ten-line Node script catches it before the browser does.

Cursor glitter

Drop in

Square sparks trailing the pointer, snapped to a 3px grid so they read as pixel art rather than a generic particle blur.

Spawning is gated by distance travelled, not by events — a 1000Hz mouse and a 60Hz trackpad give identical density. Hard cap on live particles; a tap burst replaces the trail on touch.

BitesSkip the clearRect entirely when there are no particles and nothing was drawn last frame. An idle pointer should cost nothing.

Living background

Some wiring

Instead of flat colour: a pixel grid with circuit traces and solder pads, drifting against the scroll, plus a canvas of slow dust motes.

The grid is pure CSS gradients on a fixed layer, offset by scrollY × -0.12. Dust borrows the palette from CSS custom properties, so it changes with the theme.

BitesTurn it right down on pages people actually read. Ours drops to 6% opacity on the dashboard — good to glance at, terrible to read over.

The welcoming party

Some wiring

Machines asleep at the very bottom of the page. Reach the end and they wake, walk about at their own paces, turn at the walls and hop — every few hops, one clears the top entirely.

Placed after the footer, so an IntersectionObserver firing on them genuinely means "reached the end". Each walker carries its own speed, hop rhythm and direction.

BitesFlip only the sprite, never the wrapper — mirroring the wrapper writes any label backwards. And overflow: visible on the container, or they can't actually escape.

Rope scrollbar

Drop in

The scrollbar as a length of braided rope.

::-webkit-scrollbar-thumb {

Diagonal bands make the braid; a dark selvedge down each edge makes it a rope rather than a stripe. scrollbar-color is the Firefox fallback.

Controls

Two switches, made into objects instead of toggles.

Pull-cord day/night

Some wiring

A chain hanging from the top corner with a bulb and a ring. Pull it and the lights change. It swings when you touch it, not only when you pull it.

A real <button> with aria-pressed and one constant accessible name — the chain is decoration layered on top. The bulb shows state visually.

BitesA toggle keeps one name and lets aria-pressed carry the state. Changing the name and the state together announces a contradiction.

The light being swallowed

Rebuild

Going dark doesn't repaint — a sheet of the lit colour is left over the page and collapsed into the bulb, with ninety sparks dragged in after it.

clip-path: circle() animated from 150% to 0 at the bulb's coordinates, with steps() so it moves in jumps. The particle engine gains an implode mode: sparks accelerate toward a target and snap the last stretch.

Themes that fade

Drop in

Colour, background, shadow and border cross-fade over 520ms instead of snapping.

BitesTwo traps. Never transition all — it drags layout and transforms in and everything feels like treacle. And suppress transitions for the first paint or the page cross-fades from the browser default on load; lift that suppression with requestAnimationFrame and a short timer, because rAF never fires in a background tab.

Waiting & travel

The waiting screen

Rebuild

Click a link that leaves the page and the mark takes over: the wings, a line worth reading, and one of five scenes at random — rain, snow, a flock crossing, a party, or a big machine drinking tea while building a robot.

A delegated click handler decides whether a link genuinely leaves (same origin, no modifier key, not an anchor on this page), calls preventDefault, shows the scene, and navigates on a timer.

BitesThree things. The navigation must be on a timer that fires no matter what, or a slow scene traps people. Handle pageshow or the Back button returns to a cached page with the veil still up. And if your loader script loads after your mount call, the sprite host is never mounted and your beautiful animation draws nothing.

nav.js → SCENES, LINES

A 404 that survives

Some wiring

The one page that has to work when the stylesheet is the thing that's missing. It carries enough of its own styling inline to stay readable with nothing else loaded.

BitesIts paths must be absolute from the site root. A 404 is served for any missing address at any depth — relative paths resolve against the URL that was asked for, so /a/b/c goes looking for its stylesheet in /a/b/. Ours shipped broken and the build was green.

Characters that do a job

Both of these carry information. Neither is decoration that wandered in.

The guard on the door

Rebuild

Paces the width of the sign-in panel and turns at each end. Every nine seconds he plants, his eyes go red, a hand comes up, and he says one of six things — each true of that page, including the one about not reusing a password.

Two sprite states swapped by remounting the same host. Pacing is a CSS steps() animation; the speech is a bubble with aria-live.

BitesWhat he says must ignore the motion switch. The warning is content; only the pacing is motion.

guard.js

Help behind a white flag

Some wiring

A corner button that opens a small chat. It answers from a hand-written table of the site's own content — no network, no model, and it says when it doesn't know rather than inventing.

Keyword scoring against a list of entries, each with a suggested-question chip. Suggestions rotate to what you haven't asked yet.

Bites"Hide" should minimise, not disappear. A control someone has to go hunting for in a footer is a control they've lost — ours shrinks to its own icon and stays put.

Accounts & data

The front-end mockup, then the real thing — and the site tells the truth about which one it currently is.

The gate

Drop in

Member pages redirect before a single pixel of member content paints.

A blocking script in <head>, before the body is parsed, keyed off data-guard="members" on <html>. Uses location.replace so Back doesn't bounce.

BitesFail closed. If the session module didn't load, redirect — "cannot tell" must never mean "come in". And say plainly that a front-end gate is a door, not a lock.

guard.js (head) · session.js

Remember me

Some wiring

Opt-in. The session moves to localStorage as well as the tab, and the form fills in the address next time. Never the password.

Signing out clears both stores and tells other open tabs via the storage event. Kept sessions expire after 30 days.

BitesGive people a way out from the page the remembered address appears on — a "Not you?" control. Otherwise the only escape from someone else's session is knowing to find a button inside it.

A real back end, without an SDK

Rebuild

Supabase auth and REST over plain fetch. Pulling a library off a CDN would break both the no-network rule and the CSP.

POST /auth/v1/signup                   → create account, password hashed server-side
POST /auth/v1/token?grant_type=password → sign in
GET  /auth/v1/user                     → who the server says you are
POST /rest/v1/members                  → your row, user_id filled by a trigger

Two config values decide everything. Filled in, the site does real accounts; empty, every call reports no-backend and it falls back to the mockup with nothing broken. The warning on the form rewrites itself — "do not use a real password" stops being true the moment a server is hashing it.

BitesRow Level Security is what protects the data, not the key being secret — the publishable key is designed to sit in browser JavaScript. Turn RLS on before anything else, and fill user_id from the token with a trigger rather than trusting whatever the browser sends. The service_role key must never appear in the repository.

Content Security Policy that's actually in force

Some wiring
default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline';
script-src 'self'; font-src 'self'; connect-src 'self' https://*.supabase.co;
form-action 'none'; base-uri 'none'
BitesCheck it's actually being sent. Ours lived in vercel.json — and GitHub Pages doesn't read that file, so the live site sent no policy at all while the docs claimed it did. A <meta http-equiv> tag works on any host. frame-ancestors can't be set that way and has to stay a real header.

Load order

Order matters more than you'd expect. Two of our bugs were purely this.

The rule that saved the most time: anything injected into the DOM after the sprite engine's mountAll has run must mount its own sprites. The waiting screen's bird drew nothing at all for a day because the overlay appeared correctly and the sprite inside it had never been mounted — it looked like it worked.

Every feature above is plain HTML, CSS and JavaScript. No framework, no build step, no runtime network request except the one to Supabase.
